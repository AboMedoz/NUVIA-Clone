# Routing and providers

`app/App.jsx` composes preview mode and AuthProvider. `routes.js` owns known hash routes; `access-policy.js` guards private routes and resumes saved onboarding; AppRouter orchestrates existing feature screens and account form state. Account markup lives in `features/auth/AuthPage.jsx`, not a duplicate router screen.

Keep the existing request generation/cancellation and token-consumption guards when extending routes. Preview routes must not perform real authentication mutations. There is no new client router or global-store dependency in this restructuring.

Account workspace routes load `features/product/ProductWorkspace.jsx` lazily, reusing the existing product provider and shell. Connected destinations include surveys/builder, feedback/detail, overview/analytics, reports, assistant, branches, team and business-page settings. Collection routes `#/s/:token` and `#/b/:slug` remain anonymous. `#/team/accept?token=...` and the `team-accept` alias save invitation continuation to the protected server session before removing the token from the URL. The nonsecret session `pendingInvitation` flag resumes joining after signup, verification or login and prevents accidental business onboarding. Acceptance or explicit decline clears continuation; no invitation bearer is saved in browser storage.

Shared request hooks abort old route/scope requests. Shared filters serialize date boundaries in the workspace reporting timezone, omit blank values, and encode segment question IDs using the public API contract. Role-aware controls support Owner/Manager/Viewer, while server authorization remains authoritative. Product routes show persisted data; only browser test fixtures and explicit previews contain illustrative analysis.

Changing display language preserves same-workspace drafts/conversations. Identity, workspace and permission-scope changes reset product state. Feedback search resets pagination before request effects commit. Analytics, feedback and reports refresh at most every 30 seconds while their tab is visible; unmount stops polling. Queued processing, missing capabilities, insufficient evidence and failed model requests have distinct status/retry behavior.
